Dynamic Menu Extensions via JSON
To implement dynamic menu additions without scanning for a specific file (e.g., no "menu_extensions.json"), we can extend the existing ModManager.cs logic during mod loading. When parsing each mod's mod.json (already done in LoadMod), check if it contains a "menus" array (as List<menudefinition> or similar). If present, merge those menus/tabs/elements into the global _menus list in MenuManager.cs at runtime. This keeps it simple: mods opt-in by including "menus" in their root JSON.</menudefinition>

Merge Strategy: In ModManager.LoadMod, after deserializing ModInfo, if modInfo has a "menus" property (add to ModInfo class), iterate and add to a shared list. Then, in MenuManager.LoadMenuConfig, append these after loading the base config. For conflicts (e.g., same menu name), prioritize base or use overrides (e.g., merge elements into existing menus).
Tab Handling: Since tabs are already in MainMenu.json as "tabs" array, merged "menus" could include new tabs (e.g., a mod adds a "Mods" tab with custom buttons). SwitchTab would handle dynamically.
Workshop Compatibility: Works for local/Workshop mods—JSON is lightweight, no extra files.

This makes menus extensible without hacks, aligning with workshop subscriptions adding tabs (e.g., a mod for "Quest Builder" adds a tab).

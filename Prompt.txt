PROJECT CONTEXT – SiegeEngine / CastleBuilder (May 2026)
Vision & End Goal
SiegeEngine is a custom C# game engine built for MMORPGs that prioritizes moddability, extensibility, and security from the ground up. The engine supports real-time multiplayer with hundreds of players, strong client prediction, authoritative server validation, reconciliation, frustum culling of sensitive data, ray-cast occlusion checks, and other anti-cheat measures.
A core philosophy is that the IDE/editor is built on top of the engine itself (CastleBuilder). This makes the entire tool self-moddable and self-hosting. The engine and editor share the same core systems (rendering, events, UI, assets) but maintain heavy separation of concerns between core engine code and IDE/editor code.
The ultimate goal is to empower solo hobbyists, small teams, and communities to build, mod, share, and play custom MMORPG-style games with minimal friction — treating game creation itself as an engaging “meta-game.”
Architecture Overview

Core Engine (SiegeEngine/): Rendering (OpenGL via Silk.NET/GLFW), asset pipeline (mature custom FBX parser for meshes, skeletons, animations, bones, materials), Entity/Component system (traditional OOP components), EventBus + strongly-typed IEvent (central communication backbone for UI ↔ C#, client ↔ server, editor events, etc.), GameSystems, Scenes, custom HTML/CSS/JS UI framework, mod loading, Steam networking.
Editor / IDE (CastleBuilder/, ToolChest/, MapRoom/, Keystone/, ReadingChamber/): Dockable/resizable IDE panels, context switching (terrain, scene editor, animator, etc.), BlueprintManager, project/scene management, asset browser, properties inspector, brush tools, animation timeline, etc. Built directly on top of the engine’s UI, events, and rendering.
Server (Citadel/): Authoritative GameServer, ServerValidationSystem, EntityDeltaTracker, spatial grid, occlusion, movement/inventory/combat validation, delta compression.
Launcher / Bootstrap (Trebuchet/, Foundation/): Launcher.Start() → initializes contexts, EventBus, ModManager, MenuPanel, SceneManager, PanelManager, etc.
Other folders (MapRoom/, ToolChest/, etc.): Specific editor scenes and panels.

Key Design Principles

Strong separation of responsibility between core engine and editor/IDE code.
EventBus + IEvent (with Serialize/Deserialize) is the single source of truth for all communication.
Modding is first-class: mods can override/extend via JSON configs + fully-qualified namespace hooks (e.g. SiegeEngine.AssetParsing.FBXParser.Load). Mods load from local mods/ directory and Steam Workshop.
The custom UI system (HTML/CSS parser + JSContext/JSEvaluator + DataHook system) is production-grade and will be used for both editor and in-game UI. It is very feature-rich; extension (Lua, full V8, etc.) is planned but not immediate priority.
Networking supports pure Steam P2P, hybrid authoritative server, and dedicated server as distinct options.
Unity asset interop (UnityAssetLoader, meta files, prefabs) is deprecated and not actively developed.

Current State & Priorities

Core rendering, asset pipeline (FBX), event system, mod loading, server validation, and terrain editor (brush sculpting, heightmaps, ghost preview, wireframe/textured modes) are solid and production-ready.
Panels and overall editor efficiency feel great.
WIP areas (next focus): Solidifying clean editor vs runtime separation (especially CameraController and PlayerMovement), client prediction + reconciliation, real-time multiplayer editing collaboration, entity replication maturity, and continued new feature development on a rock-solid foundation.
Lots of Console.WriteLine debug statements remain — expected in active development.

When the user clicks "Create Terrain" in NewTerrainPanel (whether a 2048×2048 custom flat or a real GeoTIFF like the 3200×1525 USGS10m output), the temp TerrainCreatorScene successfully loads or generates the full-size heightmap array. ProjectSettings.Current.SetCurrentTerrain correctly stores the large reference (logs explicitly show "shared heightmap reference set (3200x1525)" or "2049x2049"). The GeoTiffParser runs, reports correct dimensions, correct min/max heights (2501.6m to 4344.0m), correct scale, and even saves the debug PNG. The central store now holds the real large array.

Immediately after closing the NewTerrainPanel, the user clicks the button that triggers MenuCommands.OpenEditorScene. This opens SceneEditorPanel, which calls EditorScene.LoadProjectData. The central-store branch is hit ("Using terrain from central store (3200x1525)"), the SceneData is copied, ActivateCurrentGameScene runs, a new TerrainCreatorScene is instantiated, and LoadTerrain is called again on the same file. All the loading logs repeat with the same correct 3200×1525 numbers.

Yet the final rendered grid in the Scene Editor panel is tiny — visually squished into a very small area on screen, as if the mesh was built for a 200×200 default terrain instead of the actual loaded dimensions. The heightmap array itself is the large one (confirmed by the repeated correct loading logs), but the visible mesh, camera positioning, and world scaling do not match the true size. The terrain appears as a tiny patch in the middle of the viewport instead of filling the expected world space.

This exact same heightmap renders at full correct size and scale when used directly in a standalone TerrainCreatorPanel. The discrepancy only appears when the terrain is created through NewTerrainPanel and then displayed through the EditorScene → TerrainCreatorScene path in SceneEditorPanel. The central store has the correct data, the loading code has the correct data, but the final rendered output in the editor does not.

We are building a professional IDE-style docking system for the game engine editor where users can freely drag any splitter bar at any level of nesting to resize adjacent panels in real time with smooth immediate visual feedback, exactly like Visual Studio or other modern IDEs. The system uses a recursive tree of DockSplitNode and DockTabbedNode objects that correctly compute layout, render splitters, and handle input for both splitters and panels.
The current behavior is that when the mouse is moved while holding the button down on a splitter, the panels render in the wrong location during the drag. Specifically, the horizontal position of the panels is often incorrect (frequently appearing at X=0 or some stale offset) while the mouse is actively moving. Vertical dragging works correctly, but horizontal dragging shows this persistent rendering offset during mouse movement. When the mouse stops moving (even if the button is still held down) the panels instantly snap to the correct final position.

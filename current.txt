We are working on SiegeEngine.Core.UI — a professional, extensible UI system for a real-time multiplayer game engine that supports hundreds of floating/docked panels, modded content, HTML overlays, and an in-game IDE.

We have a “perfect” BasePanel.cs + PanelChrome.cs combination where:

This is achieved by carefully ordering draws inside BasePanel.Render(), with a full-panel scissor, multiple DepthTest disables, viewport restores, and a final full-window reset at the end of every panel.

The problem with the current approach:
Every single panel’s Render() method is manually managing OpenGL state (ScissorTest, Viewport, DepthTest) in a fragile, per-panel way. This creates “band-aid” code: dozens of scissor/viewport/DepthTest toggles per frame, duplicated across every panel type, and easy to break when panels overlap, resize, or when new UI layers (tabs, toolbars, modded chrome) are added. It is not scalable for a professional editor that will eventually have 50–200 panels, modded UI elements, and complex docking. Debugging any new layering bug requires hunting through every panel’s Render method.
The desired future-proof architecture:
Replace the per-panel state management with a single, centralized LayeredUIRenderer that does one clean full-window pass per frame using:

A clip-rect stack (push/pop) for safe, nested clipping instead of raw scissor calls in every panel.
Explicit layers (e.g. Content, Chrome, Borders, Overlays/Hover) so draw order is declarative and impossible to get wrong.
All OpenGL state (DepthTest off, Blend on, Scissor managed by the stack) set once at the start of the UI pass.

This removes all scissor, viewport, and DepthTest code from BasePanel.Render(), PanelChrome, and every future panel. Panels will simply register what they want drawn in each layer (or call simple DrawQuad/DrawLine methods on the renderer while a clip is pushed). The IDEDockingStrategy hover icons become a final “Overlay” layer that is guaranteed on top.
Why we want to remove the render/scissor crap from each panel:

Cleaner, maintainable code — panels become pure data/logic classes instead of OpenGL state machines.
Future-proof for modding — mods can add custom chrome or overlays without touching state management.
Performance — one pass instead of N scissor switches.
Reliability — layering bugs (X under title bar, icons under chrome, etc.) become architecturally impossible.
Professional editor feel — matches how modern engines (Unity, Godot, Dear ImGui, etc.) handle UI layering and clipping.

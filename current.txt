Vision & End Goal SiegeEngine is a custom C# game engine purpose-built for real-time multiplayer MMORPG-style experiences. It was designed from the ground up with moddability, extensibility, and security as core pillars. The engine supports hundreds of concurrent players through authoritative server validation, client-side prediction, reconciliation, entity delta compression, spatial partitioning, frustum culling of sensitive data, and ray-cast occlusion checks for anti-cheat protection.

A defining philosophy is that the entire IDE/editor (Castle) is built directly on top of the game engine itself. This makes the tool self-hosting and self-moddable: every system used to run games is also used to build them. Creators — solo hobbyists, small teams, or large communities — can create, mod, share, and play custom games with minimal friction. Game development itself becomes an engaging “meta-game” where intuitive tools, seamless live previews, and instant testing keep builders fully immersed.

Architecture Overview The system is cleanly layered into four major concerns that remain strongly separated yet share the same core runtime:

Core Engine: Provides the foundational systems used by both gameplay and the editor. This includes an abstracted rendering pipeline (supporting OpenGL today with clear paths for DirectX/Vulkan), a mature asset pipeline for meshes, skeletons, animations, materials, and textures, a traditional Entity/Component architecture, a central EventBus with strongly-typed networked events, GameSystem classes for per-frame logic, Scene management, a production-grade HTML/CSS/JS-driven UI framework, mod loading, and Steam-based networking.

Editor / IDE Layer: Runs the engine in editor mode and exposes a full-featured creative environment. It includes dockable and resizable panels with snapping and live updates, context-aware switching between different editing modes (terrain sculpting, scene editing, animation authoring, 2D sprite placement, etc.), project and scene management, asset browsing, properties inspection, brush-based tools, animation timeline and blending tools, and custom in-panel 3D overlays.

Server Layer: Implements fully authoritative gameplay logic with server-side validation, spatial grids, occlusion testing, movement/inventory/combat checks, entity delta tracking, and efficient network broadcasting. The same server code can run in dedicated-server, hybrid, or editor-collaboration modes.

Bootstrap / Launcher Layer: Handles the unified startup sequence, Steam initialization, mod discovery (local + Workshop), context creation, settings management, panel and scene orchestration, and the main game/editor loop.

Key Design Principles

Strong separation of concerns between core engine code and editor-specific logic.

The EventBus + strongly-typed IEvent system (with serialization) is the single source of truth for all communication — UI ↔ code, client ↔ server, editor ↔ runtime, and mod hooks.

Modding is first-class: mods can override or extend any system through JSON configuration and fully-qualified hooks without conflicts.

The custom UI framework (HTML/CSS parser + JS context + data-hook system) powers both in-game UI and the entire editor and is designed to be production-grade and easily extensible.

Networking supports pure P2P, hybrid authoritative, and dedicated server modes from the same codebase.

All major systems (rendering, assets, events, UI, scenes) are deliberately shared between runtime and editor so the tool is inherently self-moddable.

Core Engine Systems The engine provides complete rendering abstractions, a mature FBX-based asset pipeline (meshes, skeletons, animations, bones, materials, textures), Entity/Component management with parenting and delta tracking, a rich suite of GameSystems (animation, audio with ray-traced occlusion and MP3 support, lighting, physics, client prediction, player control, environment), multiple scene types (including sandbox, terrain, 2D, model viewer, and editor scenes), and a fully-featured UI system with dockable panels, custom overlays, and dynamic JavaScript behavior.

Editor / IDE Systems The editor runs the same engine in a special editor mode. It offers context switching, project/scene blueprint management, dockable panel system with multiple layout strategies, live 3D canvas tools (terrain brush sculpting with ghost preview, heightmap I/O, wireframe/textured rendering, sprite placement with ortho camera, entity placement with selection overlays, animation timeline and blend-stack preview), asset browser, properties inspector, hierarchy/outliner, console, and a full suite of HTML-driven tool panels. All editor features communicate through the same EventBus and use the engine’s rendering and UI systems, making the entire IDE extensible via the same modding mechanisms used for games.

Prompt for Next-Phase Outliner / Properties System Redesign
We have successfully wired the focus-detection and GenericEvent flow (OutlinerHierarchyUpdate). TreeViewPanel now receives events and attempts to render a hierarchy, but the current implementation is unacceptable for the following reasons:

Hardcoded fake nodes in TerrainCreatorPanel.OnContentFocusGained (and similar places) — this is not maintainable, not modder-friendly, and not future-proof.
Selection behavior is broken: clicking a node often highlights large sections of the tree instead of the precise leaf/subsection.
PropertiesPanel still shows "No selection" or generic placeholders because we are not dynamically binding real objects.
The tree is built with raw string concatenation instead of using the existing production-grade HtmlElement / CssParser / HtmlParser system that the rest of the IDE already uses.
Overall UI looks unprofessional (poor spacing, icons, hover states, selection highlight, collapse/expand behavior).

New Architecture Requirements (strict):

Dynamic Hierarchy Generation (no hardcoded strings) Every content panel that wants to own the Outliner must override a clean virtual method GetOutlinerHierarchy() that returns a real List<ToolChest.TreeViewPanel.TreeNode> built from actual runtime data.

   * Use reflection where appropriate (e.g., inspect TerrainCreatorScene fields, _terrainScene heightmap data, active brush, scene entities, etc.).
   * Provide a clean registration pattern so mods can add their own node types without touching core files.

Reusable Node Definitions Create a small set of static-ish, strongly-typed node classes (e.g., TerrainRootNode, HeightmapNode, BrushNode, SceneEntityNode) that inherit from or implement a common IOutlinerNode interface. These nodes know how to:

   * Generate their own TreeNode representation.
   * Provide metadata for PropertiesPanel (via reflection or explicit property bags).

Leverage Existing HTML/Element System Stop using raw string templates and  replacement. Instead, TreeViewPanel should build a real HtmlElement tree (using DivElement, LiElement, UlElement, etc.) via the existing HtmlParser / CssParser pipeline.

   * This gives us proper layout, styling, hover, and JS hook support for free.
   * Add a ToHtmlElement() extension or method on TreeNode / IOutlinerNode so nodes can render themselves as proper UI elements.

Precise Selection & Hover Logic

   * Clicking a node (any level) must publish a precise GenericEvent with Hook = "ItemSelected" containing itemId, itemPath, and the actual backing object (or a reference the content panel understands).
   * Hover should highlight only the exact row (modern tree styling).
   * Selection must update PropertiesPanel immediately with reflection-based editable properties of the selected object.

PropertiesPanel Improvements

   * When it receives "ItemSelected", it uses reflection (or the node’s GetProperties() method) to dynamically build a clean property grid using the existing InputElement, RangeElement, etc.
   * Support nested objects and basic types out of the box.
   * Keep it simple but professional (no more generic "No selection" fallback once a real node is selected).

Professional CSS / Visual Polish

   * Modern, dark-themed tree (clean lines, proper indentation, subtle hover, crisp selection highlight, good typography).
   * Icons should be consistent with the rest of the IDE.
   * Collapse/expand arrows must be perfectly aligned and responsive.
   * The entire panel should feel like a professional game-engine outliner (Unity/Unreal style).

Maintain Existing Contracts

   * Keep the GenericEvent + "OutlinerHierarchyUpdate" publish-on-focus model.
   * Keep IDataAwarePanel persistence.
   * Keep one-way communication (content panels never call TreeViewPanel directly).
   * Zero breaking changes to camera mode, docking, resize, or existing panels.
Deliverables for this phase:

Updated TreeViewPanel.cs that builds real HtmlElement trees instead of string templates.
Updated PropertiesPanel.cs with dynamic reflection binding on selection.
New IOutlinerNode interface + a few example node classes (Terrain-focused first).
Clean GetOutlinerHierarchy() implementation in TerrainCreatorPanel (and stub in SceneEditorPanel).
Modern CSS updates (provide the full TreeViewPanelUI.html + any needed CSS).
Full removal of all hardcoded strings in OnContentFocusGained.

This is the professional-grade foundation we need before adding more panels or mod support.

As a user building a game in SiegeEngine IDE, the entire experience is designed to feel like a professional, self-contained creative studio that is also the game itself. You start by creating a new project through the clean modal in the File menu. This instantly sets up a folder structure with project.json, Scenes, Assets, and Mods directories, and automatically gives you a default "Main" scene inside the project data. Every project is built around a collection of scenes, where each scene is a complete, self-contained world that can hold terrain data (heightmap + color texture + normal texture), a list of placed 3D entities (models, sprites, lights, future sound emitters), and environment settings (time of day, weather, ambient lighting). The system is deliberately 3D-first but flexible enough for 2D or hybrid workflows because the viewport mode lives inside the runtime scene classes rather than being locked in the data.
The IDE itself is the editor. You see a slim top bar with context blades (Terrain, Animator, Scene Editor, Configuration) that instantly change the available tools and workspace focus. Clicking a blade publishes a context change event, which swaps panel layouts and, when you’re in Scene Editor, ensures a scene exists so you can immediately start building. The Panels dropdown always shows the right tools for the current blade (Terrain Creator for sculpting, Hierarchy and Properties for editing entities, etc.). Everything is saved automatically into the single project.json for now (we plan to split scenes into individual .scene.json files later for better Git and modding support), and the BlueprintManager handles loading, saving, and scene creation so your work persists between sessions.
Right now the system is at a solid but transitional stage: New Project and New Scene both work and create real data, the EditorScene panel opens and renders, and the context blades switch the UI layout correctly. However, the actual connection between the data model (SceneData) and the runtime scenes (TerrainCreatorScene, future full SceneEditor, etc.) is not yet live. When you switch to Scene Editor or create a new scene, you don’t yet see your terrain or entities appear in the 3D viewport, and changes you make in the terrain brush or entity placement tools do not yet write back into the SceneData.
The immediate next goal is to close that loop so the editor becomes truly usable: make the context blades and New Scene command load the correct SceneData into the active runtime scene, wire terrain sculpting and entity placement so they update the in-memory SceneData, and have Save automatically persist everything back to project.json. Once that foundation is solid, we can plug in the Hierarchy and Properties panels so you can see and edit the entities list, add the sound system testing inside scenes, and begin building the animation blending tool on top of the same scene data structure. This keeps the entire workflow feeling like one seamless meta-game where you create, test, and iterate without ever leaving the IDE.

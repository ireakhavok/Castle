The core requirement is that the brush system must remain a fully independent and reusable component because it will be needed across many different contexts in the future, including terrain height sculpting, 2D sprite and color spraying, FBX mesh vertex painting, decal placement, and potentially other creative tools. Embedding the controls directly into any single panel would create tight coupling and make future reuse difficult, so the correct architectural decision is to keep BrushPanel as a standalone, well-tested module that can be opened from anywhere while still feeling integrated when used over a 3D viewport.
The current implementation feels disjointed because BrushPanel inherits the full BasePanel chrome, including a title bar, close button, and docking behavior, which causes it to fight for input focus and z-order with the underlying terrain viewport. The goal is to solve this without sacrificing reusability by adding a lightweight "overlay mode" to BrushPanel that allows it to be opened as a frameless, alpha-backed, right-positioned floating control surface that stays on top of the viewport without stealing its input or requiring the user to manage another full window.
To achieve this, BasePanel will gain a simple ShowTitleBarAndChrome property that defaults to true but can be set to false when the panel should behave as a minimal overlay. BrushPanel will expose a new OpenAsOverlay method that accepts a desired screen position and an optional parent panel reference. When called this way, the panel will automatically position itself to the right side of the terrain viewport, use a semi-transparent dark background, suppress the title bar and standard chrome, become non-draggable by default except for a small grip area, and set a high RenderOrder so it renders cleanly on top without interfering with the main 3D interaction.
This approach satisfies both the immediate need for a pleasant, Blender-like integrated feel inside the Terrain Creator and the long-term requirement for a single, testable, reusable brush component that can be opened from the 2D sprite editor, future mesh painting tools, or any other context. Because the brush state and logic remain centralized in one place, values can be easily set, validated, and propagated across different panels during regression testing and development. The implementation will focus on making the overlay mode feel native and out of the way while preserving the full-featured panel behavior when opened standalone.

1. Core Architecture & Authority

Single spatial authority — PhysicsComponent (on every entity that needs collision).
It owns Position, Rotation, Velocity, AngularVelocity, mass, damping, friction, restitution, sleeping state, and the collider shape.
BodyType drives simulation behaviour:
Static — infinite mass, never moves, never integrates.
Kinematic — invMass = 1 for contact response (so it can be pushed out of geometry), gravity is optional (controlled by IsGrounded), X/Y motion is owned by gameplay code (PlayerMovement), Z is owned by physics.
Dynamic — full rigid-body integration with real mass.

The same PhysicsComponent instance is shared between the player object, the entity on the server, and the renderer. There is never a duplicate transform.

2. Simulation Schedule (PhysicsWorld.Step)
textaccumulator += deltaTime
(clamp accumulator to ≤ 5× FixedTimestep)

while accumulator ≥ FixedTimestep:
    Integrate(FixedTimestep)
    DetectAndResolveContacts(FixedTimestep)
    accumulator -= FixedTimestep

// residual time left in accumulator
for every non-sleeping body:
    RenderPosition = Position + Velocity × residual

Fixed or variable timestep is selectable at runtime.
The residual is never applied to the authoritative state; it only exists for visual sampling.

3. Integration (Integrate)

Dynamic bodies
Apply linear & angular damping → add gravity → advance position with the new velocity (semi-implicit Euler).
Kinematic bodies (the player capsule)
If IsGrounded (from the previous frame) → clamp residual downward velocity to ≥ 0.
Else → apply gravity.
Advance only the Z component of Position.
X/Y are left untouched because PlayerMovement already advanced them earlier in the frame.


Order of operations in a frame is deliberate:

PlayerMovement writes desired horizontal velocity and advances X/Y.
PhysicsWorld.Step integrates vertical motion and then resolves all contacts.
Contacts are therefore the last write to Position.

4. Collision Detection & Contact Generation
Shapes currently supported:

CapsuleShape — vertical capsule for the kinematic player (feet at Position, radius 0.4 m, height 1.8 m).
ObbShape — oriented bounding box for dynamic props and kinematic scenery that has authored bounds.
TriangleMeshShape — full triangle mesh + binary AABB tree for static geometry (walls, complex models). Narrow-phase queries only the overlapping subset of triangles.
HeightfieldShape — first-class terrain collider that samples the existing heightmap (IHeightProvider). No discrete snap, no special post-step clamp.

Contact generation is shape-abstracted:

Capsule vs Capsule, Capsule vs OBB (5 samples along the capsule axis), Capsule vs TriangleMesh (AABB-tree + 5 samples), OBB vs OBB, OBB vs Mesh AABB, Capsule/OBB vs Heightfield.
Heightfield contacts produce a normal via finite differences so slopes are correctly tilted.
For the player capsule vs heightfield a supporting contact whose normal is within SlopeLimitDegrees (default 50°) sets IsGrounded = true.

All contacts are collected into ContactManifold objects that carry the two bodies (or body + null for heightfield) and an array of contact points (position, normal, penetration).
5. Contact Resolution (ResolveManifold)
Sequential-impulse solver with position correction:

Statics have infinite mass.
Dynamics use real mass.
All kinematics receive invMass = 1 so they can be pushed out of static geometry while still feeling gravity.
Position correction uses a soft percent bias (0.8) + slop (0.01 m).
Special case for kinematic + heightfield: the position correction is forced purely vertical. The tilted normal is still used for the velocity projection and friction, but never injects lateral displacement into Position. This is the standard kinematic-character response that keeps the player from sliding sideways on slopes while remaining fully contact-driven.
Velocity projection cancels the component of relative velocity along the contact normal (with restitution).
Friction: stronger static friction stick on heightfield (mu ≥ 1.2 and a velocity-nulling stick when tangential speed is low) to prevent residual slope creep.

After resolution the IsGrounded flags that were set during contact generation remain for the next Integrate.
6. Character Controller Specifics (Phase-1)

Player is always forced to BodyType.Kinematic + fixed vertical capsule.
Horizontal motion is completely owned by PlayerMovement (acceleration, deceleration, camera-relative input, blend-stack drive).
Vertical motion, gravity, and all collision response are owned by physics.
IsGrounded, SlopeLimitDegrees, and StepHeight travel with the component through serialisation and the pure-client Play payload.
Step-up / step-down logic that would use StepHeight is still future work; the field is present so the architecture is ready.

7. Sleeping / Islands / Events (current state)

Sleeping fields (IsSleeping, IslandId, SleepThreshold, SleepTimer) exist on the component but are not yet driven by an energy/velocity deactivation system.
No contact / wake / sleep / joint-break events are published on the EventBus yet (the PhysicsCollisionEvent type exists but is not generated by the solver).
Broad-phase is currently a naïve pair loop; a spatial hash / BVH for thousands of bodies is Phase-2/3.

8. Integration with the Rest of the Engine

PhysicsSystem (a GameSystem) keeps the body list in sync with entities that carry a PhysicsComponent and calls World.Step every frame.
Height provider is injected from the live scene state / heightmap so the heightfield always sees the current terrain.
Rendering and camera sample only the visual RenderPosition; simulation and networking continue to use the discrete authoritative Position.
The same physics world runs under dedicated server, P2P host, or listen-server; clients predict their own kinematic controller; other dynamic bodies may optionally be predicted later.

That is the complete current Phase-1 physics system: a deterministic fixed-timestep sequential-impulse contact solver with first-class heightfield, real triangle narrow-phase, kinematic character response, and a clean visual residual extrapolation that finally eliminated the growing freefall stutter.

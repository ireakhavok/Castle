The UI system is entirely HTML/CSS/JS driven through UIOverlay, and panels are movable and dockable containers that can render a Scene inside them, with optional UI overlays on top. Scenes control the rendering pipeline, object lifecycle, camera behavior, and what exists in the viewport. We are not using EditorScene or SandboxScene for terrain work.
We have the original USGS DEM file USGS_13_n37w094.tif as our starting terrain data. The goal is to build a clean, fully internal terrain creation workflow with zero external dependencies at runtime.
The exact plan we are following is this: We will modify the file DevMenu.html to add a new sidebar button labeled "Terrain". In TerrainCreatorScene the user begins in god-mode fly camera so they can freely fly around and inspect the loaded terrain. Future features such as brushes and editing tools will be added inside this same scene later.
